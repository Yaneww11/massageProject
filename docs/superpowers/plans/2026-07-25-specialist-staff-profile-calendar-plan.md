# Specialist & Staff Profile Calendar Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give `ProfilePage` (`/profile/`) a third role — specialist — with a read-only weekly calendar of their own bookings, extend the existing (currently superuser-only) staff branch into the same calendar with a specialist picker, and fix the underlying permission system so both are properly assignable through the Django admin.

**Architecture:** Add a `Specialist.user` link and two real Django permissions (`view_all_reservations`, `view_specialist_reservations`) on `Reservation`. `ProfilePage.get_context_data` resolves one of three roles (`client` / `specialist` / `staff`) and, for the latter two, builds a server-side-computed week grid (a pure helper function, no new JS/JSON) rendered by a shared template partial. The existing client branch is untouched.

**Tech Stack:** Django server-rendered templates, vanilla JS (reusing the existing review-modal pattern already in `my_profile.html`), no new libraries or endpoints.

## Global Constraints

- Permission codename is `view_specialist_reservations` (correct spelling) — not `view_speacilist_reservations`.
- Week starts on Monday.
- Role precedence when a user qualifies for more than one: `staff` (`view_all_reservations`) wins over `specialist`.
- Calendar is read-only: clicking a booking only shows details and links to the existing edit/delete views — no new write endpoints.
- No new JSON endpoint and no calendar JS library — week/specialist navigation is a full page reload via GET params (`week`, `specialist_id`).
- No hardcoded hex colors in CSS — use the existing `var(--...)` custom properties from `theme_overrides.html`.
- Use `site_config.specialist_singular`/`specialist_plural` for specialist terminology in new UI text — never hardcode "специалист".
- Any new static UI string must be added to both `locale/bg/LC_MESSAGES/django.po` and `locale/en/LC_MESSAGES/django.po`, then compiled, per `CLAUDE.md`.
- The existing `client` branch of `ProfilePage` (queries, context keys, template markup) must not change behavior.

```python
def _time_to_minutes(t):
    return t.hour * 60 + t.minute


def _build_week_calendar(specialist, week_start):
    week_days = [week_start + timedelta(days=i) for i in range(7)]

    working_hours_by_day = {
        wh.day_of_week: wh
        for wh in WorkingHours.objects.filter(specialist=specialist)
    }

    reservations = list(
        Reservation.objects.active()
        .filter(specialist=specialist, date__range=(week_days[0], week_days[-1]))
        .select_related('user')
        .order_by('time')
    )
    reservations_by_date = {}
    for r in reservations:
        reservations_by_date.setdefault(r.date, []).append(r)

    user_ids = {r.user_id for r in reservations}
    visit_counts = {}
    if user_ids:
        visit_counts = {
            row['user_id']: row['c']
            for row in Reservation.all_objects.filter(
                specialist=specialist, user_id__in=user_ids, status=Reservation.STATUS_COMPLETED,
            ).values('user_id').annotate(c=Count('id'))
        }

    if working_hours_by_day:
        window_start = min(_time_to_minutes(wh.start_time) for wh in working_hours_by_day.values())
        window_end = max(_time_to_minutes(wh.end_time) for wh in working_hours_by_day.values())
    else:
        window_start, window_end = 8 * 60, 20 * 60
    window_span = (window_end - window_start) or 1

    days = []
    for day_date in week_days:
        wh = working_hours_by_day.get(day_date.weekday())
        day_entries = []
        for r in reservations_by_date.get(day_date, []):
            start_minutes = _time_to_minutes(r.time)
            end_minutes = _time_to_minutes(r.end_time)
            day_entries.append({
                'reservation': r,
                'top_pct': round(max(0.0, (start_minutes - window_start) / window_span * 100), 2),
                'height_pct': round(max(0.0, (end_minutes - start_minutes) / window_span * 100), 2),
                'visit_count': visit_counts.get(r.user_id, 0),
            })
        days.append({'date': day_date, 'working_hours': wh, 'reservations': day_entries})

    hour_marks = []
    first_hour = window_start // 60
    last_hour = -(-window_end // 60)
    for h in range(first_hour, last_hour + 1):
        minute = h * 60
        if minute < window_start or minute > window_end:
            continue
        hour_marks.append({
            'label': '%02d:00' % h,
            'top_pct': round((minute - window_start) / window_span * 100, 2),
        })

    return {'days': days, 'hour_marks': hour_marks}
```

```python
    def _add_calendar_context(self, context, specialist):
        today = date.today()
        context['today'] = today

        week_param = self.request.GET.get('week')
        requested = today
        if week_param:
            try:
                requested = datetime.strptime(week_param, '%Y-%m-%d').date()
            except ValueError:

        week_start = requested - timedelta(days=requested.weekday())

        context['calendar_specialist'] = specialist

        context['prev_week'] = week_start - timedelta(days=7)
        context['next_week'] = week_start + timedelta(days=7)

        if specialist is None:
            context['calendar'] = None
            context['bookings_today'] = 0
            context['bookings_this_week'] = 0
            context['next_client_reservation'] = None
            return

        context['calendar'] = _build_week_calendar(specialist, week_start)

        week_end = week_start + timedelta(days=6)
        week_reservations = Reservation.objects.active().filter(

        )
        context['bookings_this_week'] = week_reservations.count()
        context['bookings_today'] = week_reservations.filter(date=today).count()

            week_reservations.filter(date__gte=today).order_by('date', 'time').first()
```
