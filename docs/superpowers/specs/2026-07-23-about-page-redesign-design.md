# About Page Redesign — Design Spec

Date: 2026-07-23

## Goal

Redesign the About page (`templates/pages/about.html`) to match the visual
style of a Claude-generated artifact mockup, while making its content
dynamic (studio bio, stats, credentials, FAQ) instead of hand-written HTML.
Also restyle and extend the site-wide nav header to match the same mockup.

Reference artifact: https://claude.ai/code/artifact/ab55cab0-cbc2-449f-b5f3-2a89946acdc6
(hero section confirmed visually: small tracked "ABOUT" eyebrow label, large
serif heading, centered subtitle, two-column photo+text info block below.
Lower sections — stats/credentials/FAQ — could not be scrolled into via
automation; those are designed fresh in this spec, matching the confirmed
visual language.)

## 1. Data model — `BusinessInfo`

Add three JSON fields to `massageProject/main_app/models.py`:

```python
class BusinessInfo(models.Model):
    ...
    stats = JSONField(default=dict, blank=True)
    credentials = JSONField(default=dict, blank=True)
    faq = JSONField(default=list, blank=True)
```

**`stats`** — flat dict of display-ready strings, single value shared across
languages (not translated):

```json
{
  "years_of_practice": "8+",
  "clients_served": "500+",
  "average_rating": "4.9",
  "certifications_count": "12+"
}
```

**`credentials`** — two grouped lists, each entry with title/subtitle/year/description.
Registered for translation (bg/en shadow fields via modeltranslation):

```json
{
  "training": [
    {"title": "Swedish Massage Certification", "subtitle": "Vienna Institute", "year": "2019", "description": "..."}
  ],
  "recognition": [
    {"title": "...", "subtitle": "...", "year": "...", "description": "..."}
  ]
}
```

**`faq`** — flat list of question/answer pairs. Registered for translation:

```json
[
  {"question": "...", "answer": "..."}
]
```

### Translation registration (`translation.py`)

Add `'credentials', 'faq'` to `BusinessInfoTranslationOptions.fields`. `stats`
is left out (untranslated — values are numeric/format-neutral).

### Admin (`admin.py`)

No fieldset changes required — the three new fields render automatically via
Django's default JSONField widget in `BusinessInfosAdmin` (already a
`TabbedTranslationAdmin`, so `credentials`/`faq` get their own bg/en tabs
matching existing fields; `stats` appears once, untranslated).

### Migration

New migration `0027_businessinfo_stats_credentials_faq.py` (or similar
autogenerated name) adding the three fields, defaults as above.

## 2. Header (`templates/partials/header.html`, `staticfiles/css/layout/header.css`)

### Link structure

Replace the current 5 links with 6, matching the artifact:

| Label (trans key) | Target |
|---|---|
| Home | `{% url 'index' %}` |
| Services | `{% url 'index' %}#services` |
| Gallery | `{% url 'index' %}#gallery` |
| About | `{% url 'about_page' %}` |
| Reviews | `{% url 'about_page' %}#reviews` |
| Contacts | `{% url 'index' %}#contacts` |

Apply to both the desktop `.nav-links` and the mobile slide-in menu (same
list, one `<nav>`).

Add `id="reviews"` to the comments `<section>` in `about.html` so the Reviews
link has somewhere to land.

### Visual restyle

- Logo stays image-only (no wordmark text — the commented-out `logo-text`
  paragraph stays commented out).
- Adjust `.navbar` padding, `.nav-links a` weight/letter-spacing, and
  `.navbar-cta` to a solid pill shape (larger `border-radius`) to feel closer
  to the artifact's cleaner, more spaced-out nav.
- All colors continue to use existing `var(--primary-color)`, `var(--bg-paper)`,
  etc. — no new CSS variables needed, no hardcoded hex values (per the
  `SiteConfiguration`-driven theming convention in CLAUDE.md).
- No functional changes: language switcher, user menu dropdown, mobile
  hamburger, auth-modal triggers, and `site_config.booking_enabled` gating on
  the CTA all stay as they are.

## 3. About page (`templates/pages/about.html`, `views.py`, `staticfiles/css/pages/about.css`)

### View changes (`AboutPage.get_context_data`)

Remove `context['specialist'] = Specialist.objects.first()` — no longer
consumed by the template. (`Specialist` import in `views.py` stays if used
elsewhere in the file; only remove this now-orphaned line.)

### Template sections, top to bottom

1. **Hero** (new) — static, translated via `{% trans %}` (Rosetta-managed,
   no DB field):
   - Eyebrow label: "ABOUT" / Bulgarian equivalent
   - Heading (`<h1>`): "The story behind the studio"
   - Subtitle: "A personal practice built on training, attention, and years
     spent refining a craft — here is the short version."

2. **Info** (modified) — two-column layout:
   - Photo: `business_info.main_image`
   - Text: `business_info.description` only (drop `specialist.description`
     entirely)

3. **Stats** (new) — 4 cards, each showing a value from `business_info.stats`
   and a static translated label ("Years of practice", "Clients served",
   "Average rating", "Certifications"). Each card renders only if its
   specific value is present in the dict; if all 4 are missing, no stats
   section renders.

4. ~~What guides the work~~ — omitted entirely, not built.

5. **Credentials** (new) — renders only if
   `business_info.credentials.training` or `.recognition` is non-empty.
   Within it:
   - "Training" sub-list renders only if `.training` is non-empty
   - "Recognition" sub-list renders only if `.recognition` is non-empty
   - Each entry shows title, subtitle, year, description

6. **FAQ** (new) — renders only if `business_info.faq` is non-empty. Each
   entry rendered as a CSS-only `<details>`/`<summary>` accordion item (no
   new JS).

7. **Reviews/Comments** (unchanged) — existing carousel, comment form, and
   "view all comments" link stay exactly as they are; only gains
   `id="reviews"` on its `<section>` for header nav anchoring.

8. **Footer** — untouched.

### CSS

New styles added to `about.css` for the hero, stats cards, credentials
lists, and FAQ accordion — using existing tokens (`var(--font-heading)`,
`var(--primary-color)`, `var(--bg-light)`, `var(--text-muted)`, spacing
scale, etc.) rather than introducing new hardcoded values, consistent with
the theming convention. Existing `.about-me`, `.photo-info-container`,
`.info-section`, `.comments`, `.carousel-*`, `.comment-form` rules are
reused/adapted, not rewritten from scratch.

## 4. i18n

After implementation, run:

```bash
source venv/bin/activate
python manage.py makemessages -l bg -l en
# translate new msgid entries (hero eyebrow/heading/subtitle, stat labels,
# credentials sub-headings, FAQ heading, nav link labels) in locale/*/django.po
python manage.py compilemessages
```

## 5. Out of scope / explicitly not done

- No changes to `populate_db.py` / `populate_renkart.py` — new fields stay
  empty until filled in via admin.
- No changes to the footer.
- No changes to `Specialist` model itself, or its use elsewhere in the app
  (e.g. reservation flow) — only its use on the About page is removed.
- No new JS/accordion library — FAQ uses native `<details>`/`<summary>`.

## 6. Testing

- Existing tests (`tests_comments.py`) create a minimal `BusinessInfo` and
  `Specialist` for `about_page` rendering — new JSON fields default to
  empty, so those tests keep passing unchanged (no test setup edits needed).
- Add/adjust `main_app` tests to cover:
  - Stats: individual card hidden when its key is missing; whole section
    hidden when all 4 are missing.
  - Credentials: section hidden when both `training` and `recognition` are
    empty; each sub-list independently conditional.
  - FAQ: section hidden when empty list.
  - Header: new nav links resolve to expected URLs/anchors.
- Manual check in browser: both `bg` and `en` locales, both a fully-populated
  `BusinessInfo` and an empty one, desktop and mobile nav.
